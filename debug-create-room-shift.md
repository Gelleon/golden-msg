# [OPEN] create-room-shift

## Симптом
- На VPS после создания (под)комнаты происходит “сдвиг вправо”, список комнат исчезает/визуально ломается.
- После обновления страницы всё возвращается, но созданная подкомната может быть не видна/не раскрывается от родителя.

## Ожидаемое поведение
- После создания подкомнаты: список комнат остаётся на месте, родитель раскрыт, новая подкомната отображается сразу.

## Гипотезы (фальсифицируемые)
- **H1 (Scroll-lock / padding-right):** после закрытия `Dialog`/`Sheet` остаётся `body.style.paddingRight` или `overflow: hidden`, из-за чего UI “съезжает”. Проверка: снять снимок `body` стилей сразу после create.
- **H2 (Пустая выдача getRooms):** сразу после create `getRooms()` (или `getDMs()`) возвращает пустой массив/ошибку, и сайдбар на мгновение рисует пустое состояние. Проверка: логировать длины `fetchedRooms/fetchedDMs` + ошибки.
- **H3 (Некорректный parent_id / цикл):** созданная подкомната имеет неправильный `parent_id` (или цикл), из-за чего сборка дерева даёт пустой `rootRooms`. Проверка: логировать `normalizedRoom.parent_id` + количество корней/attached.
- **H4 (CSS/layout на мобильном):** проблема проявляется только в `Sheet` (mobile nav), где порталы/анимации мешают корректному пересчёту ширины. Проверка: логировать `isMobile` (по media) и факт вызова `onClose`.

## План сбора доказательств
1) Запустить Debug Server на VPS в режиме `--remote` и получить URL.
2) Включить инструментирование в `Sidebar` (create + fetch) и отправлять события в Debug Server.
3) Воспроизвести: создать подкомнату в свёрнутом родителе на VPS.
4) Снять логи `/logs?runId=pre` и определить, какая гипотеза подтверждается.
